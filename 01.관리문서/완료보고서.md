## 6. 교훈 (Lessons Learned)

### 6.1 잘된 점

1. **AP-Framework 병렬 생성 전략 효과**: Group A(기능명세서 완료 후 4종 동시 생성), Group B(화면설계서 완료 후 3종 동시 생성)를 적용하여 문서 작업 기간을 대폭 단축. 설계 문서 7종을 이틀 만에 완료.

2. **Next.js 단일 프로젝트 통합**: 초기 React+Vite+Express 분리 구조 대신 Next.js App Router로 FE/BE를 통합하여 Vercel 서버리스 환경에 최적화. 빌드·배포 파이프라인이 단순화되고 운영 비용이 절감됨.

3. **Supabase 풀스택 활용**: Auth(OAuth), DB(PostgreSQL+RLS), Storage(이미지), Admin API(탈퇴)까지 단일 플랫폼으로 처리. 별도 인증 서버·스토리지 서비스 없이 MVP를 완성.

4. **MVP 범위 조기 조정**: 오프라인·Web Push·PDF를 v1.1로 이관하는 결정을 W3에 확정. 핵심 기능 구현에 집중하여 예정보다 3주 일찍 완료.

5. **실데이터 기반 검증**: 목업 데이터 제거 후 실제 Supabase DB에 2일 연속 데이터를 누적하며 차트·증감·권장 음수량 등 전 흐름을 실환경에서 검증.

### 6.2 개선할 점

1. **초기 Tech Stack 확정 지연**: 착수 시 React+Vite+Express로 계획했으나 W3에 Next.js로 전환. 초기 설계 단계에서 Vercel 배포 환경을 고려한 Tech Stack을 확정했다면 구현 문서(인프라아키텍처 등) 재작업을 줄일 수 있었음.

2. **테스트 자동화 범위 부족**: Playwright E2E 테스트가 로그인 화면에 한정됨. OAuth 세션 주입 방법을 사전에 설계했다면 홈·기록·리포트 화면까지 자동화 범위를 넓힐 수 있었음.

3. **GitHub Issues 실시간 관리 미흡**: 구현 완료된 이슈들이 Open 상태로 방치되어 프로젝트 종료 시점에 일괄 Close. 완료 시점에 즉시 Close하는 습관이 필요.
