# 시스템 정의서

> 시스템의 기술 스택, 모듈 구성, 인터페이스 규약 및 보안 체계를 정의한다.

## 기술 스택

기본 기술 스택은 **React + Vite / Express.js / PostgreSQL (Supabase)** 환경을 사용하며, 모든 통신은 보안 강화를 위해 전 구간 HTTPS 전송을 의무화합니다.

| 영역 | 기술 | 버전 | 비고 |
|------|------|------|------|
| Frontend | React + Vite | 최신 LST | 모던 싱글 페이지 웹앱 (SPA) 및 PWA 지원 |
| Styling | Vanilla CSS | - | 모던 CSS 스타일 규격 (Flexbox, Grid, Glassmorphism 등) |
| Data Vis | Recharts | 최신 | 체중 및 음수량 시각화용 React 차트 라이브러리 |
| Backend | Express.js | 최신 LST | REST API 라우팅 및 헬퍼 서버 |
| Database | Supabase (PostgreSQL) | 최신 | 클라우드 관계형 DB 및 실시간 데이터 기능 제공 |
| Auth | Supabase Auth (OAuth 2.0) | - | 카카오, 구글 간편 인증 기능 위임 |
| Deploy | Vercel | - | 프론트엔드 정적 배포 및 API 함수 호스팅 |
| OS / Dev | macOS / Windows | - | 개발 및 크로스 브라우징 QA 환경 |

## 보안 아키텍처 및 인터페이스 규약

### 1. 전송 구간 암호화 (HTTPS)
* 프론트엔드(Vercel PWA)와 백엔드 API, Supabase DB 간의 모든 통신은 **TLS 1.3/HTTPS 프로토콜 사용을 강제**합니다.
* HTTP 요청은 서버 진입 단계(Vercel 및 Supabase Edge Router)에서 자동으로 301 Redirect를 통해 HTTPS로 승격됩니다.

### 2. 회원 인증 및 권한 부여 (JWT Token)
* 사용자가 카카오/구글 소셜 로그인을 완료하면 Supabase Auth 서버로부터 위변조 불가능하게 암호화 서명된 **JWT Access Token(유효기간 7일)**과 자동 갱신을 위한 **Refresh Token**을 발급받습니다.
* 클라이언트(PWA)는 API 요청 헤더의 `Authorization: Bearer <JWT_TOKEN>` 필드에 토큰을 실어 전송해야 합니다.

### 3. 데이터베이스 Row-Level Security (RLS) 정책
* 데이터베이스 단에서 로그인한 사용자 세션 정보(`auth.uid()`)를 기반으로 쿼리 접근 권한을 실시간 검증합니다.
* 회원정보 테이블(`users`), 반려동물 프로필 테이블(`pets`), 기록 테이블(`weight_records`, `water_records`) 등 전체 스키마에 RLS를 적용하여 소유자 이외의 다른 유저가 조회/수정/삭제 요청 시 `403 Forbidden` 에러를 반환합니다.

## 디렉토리 구조

```
프로젝트 루트/
├── src/
│   ├── frontend/               # React + Vite Client Code
│   │   ├── components/         # Reusable UI Components (+/- 버튼, 스피너 등)
│   │   ├── pages/              # 30일 필터 차트가 포함된 화면 정의
│   │   ├── hooks/              # 오프라인 IndexedDB 동기화 커스텀 훅
│   │   └── styles/             # Vanilla CSS 디자인 시스템 파일
│   └── backend/                # Express.js Server Code
│       ├── routes/             # REST API 라우트 정의
│       ├── middleware/         # JWT 토큰 검증 및 에러 처리 미들웨어
│       └── controllers/        # 오프라인 동기화(UPSERT) 및 알림 제어 로직
```

## 에러 처리 규약

| HTTP 상태 | 에러 코드 | 의미 | 응답 형식 |
|-----------|-----------|------|-----------|
| 400 | BAD_REQUEST | 입력값 오류 (범위 초과, 형식 오류 등) | `{ "status": "error", "message": "에러 설명", "details": object }` |
| 401 | UNAUTHORIZED | 토큰 누락 또는 유효하지 않은 JWT 토큰 | `{ "status": "error", "message": "인증 정보가 올바르지 않습니다." }` |
| 403 | FORBIDDEN | RLS 정책 위반 (타인 데이터 접근 차단) | `{ "status": "error", "message": "요청한 데이터에 접근할 권한이 없습니다." }` |
| 404 | NOT_FOUND | 존재하지 않는 API 엔드포인트 또는 기록 | `{ "status": "error", "message": "해당 리소스를 찾을 수 없습니다." }` |
| 500 | INTERNAL_ERROR | 서버 내부 DB 처리 오류 등 | `{ "status": "error", "message": "서버 내부 처리 중 오류가 발생했습니다." }` |
